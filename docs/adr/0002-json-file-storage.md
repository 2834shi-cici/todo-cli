# 选择本地 JSON 文件作为持久化方案

todo-cli v1 的数据量极小（个人待办清单，通常几十条以内），且需要离线可用、数据归属用户本地。我们决定用单个 JSON 文件（`~/.todo-cli/data.json`）作为持久化介质，通过 Node.js 内置 `fs/promises` 读写，自动创建父目录。

**Status**: accepted

**Considered Options**:
- **SQLite** — 支持查询、事务、并发，但对 v1 的简单增删改查来说过重，且需引入 `better-sqlite3` 等原生依赖。
- **内存存储** — 最简单，但进程退出数据丢失，不满足持久化需求。
- **云端存储** — 需登录、网络依赖、隐私顾虑，与「本地轻量工具」定位冲突。

**Consequences**: 无查询能力（需全量加载后在内存过滤）；无并发安全（见 ADR-0004）；文件损坏会丢失全部数据。这些代价在 v1 可接受，未来若数据量增大或需要查询，可迁移到 SQLite。
