# v1 不做并发控制

todo-cli 是单用户、单进程的命令行工具，正常使用场景下同一时刻只有一个进程在操作数据文件。我们决定 v1 不实现文件锁或原子写，采用最简单的「读-改-写」模式：`loadStore()` 读取整个文件到内存，修改后 `saveStore()` 整体写回。

**Status**: accepted

**Considered Options**:
- **文件锁**（如 `proper-lockfile`）— 可防止多进程并发写入，但需引入依赖，且在 Windows 上文件锁行为有差异。
- **原子写**（写临时文件后 rename）— 可防止写入过程中断导致文件损坏，但无法解决两个进程同时读-改-写的丢失更新问题。

**Consequences**: 若用户在两个终端同时执行 `todo add`，后写入的进程会覆盖先写入的，导致一条待办丢失。此风险在 v1 可接受；若未来需要支持并发，应引入文件锁或迁移到支持事务的存储（如 SQLite）。
