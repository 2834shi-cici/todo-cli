# 风险点

本页记录 todo-cli 当前代码中已知的风险点与技术债。

## 并发安全

- **风险**：`loadStore → 修改 → saveStore` 是读-改-写模式，无文件锁。若两个进程同时运行（如两个终端同时 `add`），后写入的会覆盖先写入的，导致数据丢失。
- **现状**：单进程 CLI 场景下概率低，但不是不可能。
- **缓解方向**：可引入文件锁（如 `proper-lockfile`）或原子写（写临时文件后 rename）。
  > **源码** `src/storage.ts:27-61`

## 无单元测试

- **风险**：`format.ts` 是纯函数，非常适合单元测试，但当前无测试。业务逻辑也无测试覆盖。
- **缓解方向**：添加 `vitest`，为 `formatTodos`、`addTodo`、`markDone` 写测试。
  > **源码** `src/format.ts:11-20`

## 错误处理粒度

- **风险**：`handleError` 对所有错误统一 `console.error + exit(1)`，不区分错误类型（用户错误 vs 系统错误）。
- **现状**：v1 功能简单，可接受。
  > **源码** `src/index.ts:66-71`

## 无数据迁移机制

- **风险**：`loadStore` 有旧格式（纯数组）到新格式的兼容，但仅做一次性兼容，不写回迁移后的数据。若未来 `Todo` 字段变更，需显式迁移逻辑。
  > **源码** `src/storage.ts:31-39`

## 与 ADR 的一致性

当前 `docs/adr/` 为空，无 ADR 可对照。架构决策记录在 [CONTEXT.md](../../CONTEXT.md) 的「架构决策」章节中，代码与之一致。
